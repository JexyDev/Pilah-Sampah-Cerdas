LAPORAN PEMBARUAN & PERBAIKAN SISTEM (24 SEPTEMBER 2026)

Dilaporkan oleh: Tim Fullstack Developer (Backend API & Web Frontend) Target Repositori: main (Berseka Web & API) Branch Eksekusi: fix/security-hardening-and-anti-dummy -> development -> staging -> main

1. Ringkasan Eksekutif

Telah dilakukan audit dan eksekusi perbaikan kritis (Prioritas P0 dan P1) pada codebase Berseka. Fokus utama perbaikan mencakup penambalan celah keamanan kriptografi, pembersihan hardcoded kredensial dan IP VPS, serta penguatan Data Governance (pencegahan modifikasi database produksi oleh skrip lokal/seeder). Semua kode telah tervalidasi oleh type-checker (0 error) dan berhasil di-deploy ke VPS produksi lewat jalur resmi (CI/CD GitHub Actions).

2. Rincian Task yang Terselesaikan

? Task 1: Remedi Keamanan JWT & Enkripsi Kriptografi (Prioritas P0)

  • Masalah: Terdapat fallback kunci rahasia statis yang terekspos di kode (jwtUtils.ts dan cryptoUtils.ts), memungkinkan siapapun mendekripsi sesi pengguna jika Environment Variable gagal terbaca.
  • Tindakan:
    • Menghapus semua string hardcoded ('berseka_kkn_jwt_secret_key_2026', dll).
    • Sistem kini akan melempar pesan error keras (Fatal Error) dan mematikan proses jika variabel JWT_SECRET atau AES_SECRET_KEY tidak dikonfigurasi, sehingga menjamin keamanan sesi.

? Task 2: Eliminasi Hardcoded IP VPS pada API (Prioritas P0)

  • Masalah: Layanan API masih merujuk secara statis ke http://157.10.252.252:3000, yang memicu masalah CORS dan risiko routing jika IP server berubah.
  • Tindakan:
    • Semua referensi statis diubah menjadi dinamis menggunakan process.env.API_BASE_URL (atau menggunakan relatif URL /api/v1 di frontend).
    • Catatan Sinkronisasi Tim Mobile: Penyesuaian apiBaseUrl di app_config.dart pada aplikasi Android harus dilakukan terpisah oleh tim Mobile.

? Task 3: Penguatan Data Governance & Karantina Skrip SSH (Prioritas P0)

  • Masalah: Terdapat beberapa skrip injeksi data dan migrasi di folder scripts/ yang berisiko merusak database operasional riil di VPS jika tereksekusi tanpa sengaja.
  • Tindakan:
    • IP server Staging (157.10.160.93) telah didaftarkan ke modul vpsSafetyGuard.ts.
    • Fungsi assertNotProduction() berhasil diinjeksi pada 4 skrip kritis (clean-vps-db.ts, cleanup-duplicate-schedules.ts, inject-vps-attendance-20260831.ts, insert-vps-attendance.ts). Skrip ini sekarang secara otomatis memblokir eksekusi (Exit Code 1) bila mendeteksi target adalah server VPS Produksi.

? Task 4: Pembersihan Data Semu Linimasa KKN (Prioritas P1)

  • Masalah: Ketika API sedang down atau belum ada data linimasa, aplikasi Web secara silent menggunakan konstanta palsu (TIMELINE_KKN_DATA), sehingga menipu pengguna seolah-olah data riil KKN telah tersedia.
  • Tindakan:
    • Backend (timelineKknService.ts): Fungsi auto-seed dibatasi secara ekstrem; hanya bisa berjalan saat NODE_ENV === "development" di lokal developer, tidak lagi bisa menembus VPS.
    • Web (JadwalKegiatan.tsx): Fallback fallback data palsu telah dihapus secara komprehensif. UI web kini murni hanya menampilkan empty state (tabel kosong) bila tabel jadwal di database kosong atau API tidak terjangkau.

3. Deployment & Sinkronisasi

  • Integrasi Kode (Git-Flow): Perubahan diproses dari branch fix/security-hardening-and-anti-dummy secara bertingkat (Pull Request/Merge) melewati tahapan development -> staging -> main.
  • Eksekusi VPS (CI/CD): Pipeline GitHub Actions (deploy.yml) berhasil mendeteksi pembaruan di main dan telah melakukan penarikan kode (git pull) terbaru dan me-restart layanan secara otomatis di VPS (Zero-downtime reload via PM2).
  • Quality Control (QC): Skrip otomatis pembuat dummy data (test_e2e_api.ts) sengaja diblokir dari target VPS demi kepatuhan pada kebijakan Anti-Dummy Policy yang melindungi keaslian data presensi.
