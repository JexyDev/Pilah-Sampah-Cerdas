📊 Dokumentasi Sistem Poin Berseka

Dokumen ini menjelaskan secara teknis bagaimana sistem poin untuk 5 entitas pengguna (Mahasiswa, Kelompok, DPL, Warga, dan Petugas) bekerja — termasuk formula, sumber data, dan file kode yang menjadi acuannya.

✅ Status: Live di VPS Produksi 📅 25 September 2026 🌿 Branch: main PT Makerindo — Fullstack Developer
📌 Pengantar — Mengapa ada sistem poin?

Sistem poin di Berseka berfungsi sebagai mesin gamifikasi dan evaluasi kinerja yang mengukur kontribusi nyata setiap entitas pengguna di lapangan. Semua poin dihitung secara otomatis oleh server berdasarkan data riil yang masuk dari aplikasi — tidak ada input manual dari admin.

Sumber Data Poin: Semua poin berasal dari aksi nyata pengguna di lapangan (scan QR Tempat Sampah, presensi GPS, input setoran sampah, progres program kerja) yang tersimpan di database PostgreSQL VPS (psc_db) dan dihitung otomatis oleh Backend API.
🏗️ Arsitektur SSOT — Single Source of Truth

Sistem poin dibangun dengan pola SSOT (Single Source of Truth) — semua kalkulasi terpusat di satu tempat agar tidak ada perhitungan ganda atau bocor antar role.

🎓 Poin Mahasiswa KKN
🎓
Poin Individu Mahasiswa
Presensi + Logbook + Proker — terpisah dari skor kelompok
Poin Individu = Poin Presensi + Poin Durasi + Poin Logbook - Penalti
  • Presensi Hadir → +5 poin/hari
  • Durasi (per jam) → +1 poin/jam (maks tertentu)
  • Logbook diverifikasi → +3 poin/entri
  • Proker per-step → +2 poin/step (total +6 per proker)
  • Poin individu dipisahkan dari poin proker kelompok (tidak double-count)
  • Sistem penalti (minus poin) untuk Mahasiswa telah dinonaktifkan
  • Poin proker muncul di riwayat tapi tidak mempengaruhi saldo poin individu

👥 Poin Kelompok KKN
👥
Skor Akhir Kelompok
Formula 2-Komponen — sesuai notulensi rapat BERSEKA
Komponen A (bobot 60%):
  NilaiProkerStep = rata-rata step proker kelompok (25 / 60 / 100)
  RataAnggota = rata-rata assessmentScore anggota
  KomponenA = (NilaiProkerStep + RataAnggota) / 2

Komponen B (bobot 40%):
  KomponenB = rata-rata KomponenA dari SEMUA kelompok (benchmark global)

Skor Akhir = (KomponenA × 0.6) + (KomponenB × 0.4)
  → Semua anggota kelompok mendapat skor akhir yang sama
  • Nilai Proker Step: Belum Mulai = 25, Berjalan = 60, Selesai = 100
  • Kelompok uji coba (test account) dikecualikan dari kalkulasi global
File kode: apps/api/src/services/mahasiswaPoinService.ts docs/diagram_pemisahan_poin_kkn.mmd
👨‍🏫 Poin DPL (Dosen Pembimbing Lapangan)
👨‍🏫
Skor Kinerja DPL
Formula 50-50 berdasarkan kinerja administratif & kelompok binaan
Skor DPL = (Komponen Administratif × 50%) + (Kinerja Kelompok Binaan × 50%)

  Komponen Admin = Verifikasi logbook, persetujuan proker, penilaian
  Kinerja Kelompok = Rata-rata Skor Akhir Kelompok yang dibina DPL
  • Setiap DPL membina 1 kelompok KKN (relasi 1-to-1)
  • DPL bisa melihat monitoring poin seluruh anggota kelompoknya
  • Penilaian DPL oleh mahasiswa masuk sebagai komponen assessmentScore
File kode: apps/api/src/services/dplService.ts apps/api/src/services/penilaianKknService.ts
🏘️ Poin Warga
🏘️
Poin Gamifikasi Warga
Berbasis setoran sampah + streak aktivitas + bonus komunitas
Poin Warga = Poin Setoran Sampah + Poin Streak + Poin Komunitas

  Setoran Sampah → poin berdasarkan tonase (kg) × faktor kategori
  Streak Harian → bonus poin jika setoran konsisten setiap hari
  Klaim Komunitas → poin dari kontribusi melalui warga dampingan
  • Setiap warga hanya bisa klaim 1 Tempat Sampah aktif (proteksi anti-duplikasi)
  • Data tonase bersumber dari scan QR dan validasi Petugas Residu
  • Warga dari RW berbeda tidak bisa saling klaim (strict RW scoping)
File kode: apps/api/src/services/pointService.ts apps/api/src/services/gamificationService.ts
🚛 Poin Petugas Residu
🚛
Poin Kinerja Petugas
Berbasis tonase pengangkutan & validasi setoran warga
Poin Petugas = Poin Pengangkutan + Poin Validasi Setoran

  Pengangkutan → poin per kg sampah yang diangkut dari Tempat Sampah
  Validasi → poin setiap memvalidasi setoran warga yang masuk
  Penalti (minus poin) → DINONAKTIFKAN untuk role Petugas
  • Data pengangkutan masuk dari modul Pengangkutan Sampah di aplikasi mobile Petugas
  • Petugas Residu hanya dapat mengakses data wilayah RW yang ditugaskan
  • Proteksi: sistem penalti (minus poin) untuk Petugas telah dinonaktifkan di kode

📋 Sistem Proker 3-Step — Lifecycle Program Kerja

Setiap Program Kerja KKN memiliki 3 tahapan yang masing-masing memberikan poin otomatis ke seluruh anggota kelompok. Sistem dilengkapi idempotensi sehingga retry koneksi tidak akan menduplikasi poin.

StepStatus PelaksanaanPoin DiberikanTotal KumulatifKeterangan
Step 1 DISETUJUI / BELUM_MULAI +2 PTS/anggota +2 PTS Saat DPL menyetujui usulan proker
Step 2 SEDANG_BERJALAN +2 PTS/anggota +4 PTS Saat mahasiswa update status ke berjalan
Step 3 SELESAI +2 PTS/anggota +6 PTS Saat proker dinyatakan selesai
Ditolak DITOLAK oleh DPL 0 PTS (direset) 0 PTS Seluruh poin proker otomatis dicabut

🛡️ Proteksi Sistem Poin
✅ Anti Kebocoran Poin KKN_PROKER
Poin proker tidak ikut terhitung di saldo individu mahasiswa (difilter di level repository).
✅ Anti Duplikasi (Idempoten)
Setiap poin proker diberi tag unik [ProkerID:<id>:STEP], retry tidak akan double-count.
✅ Penalti Dinonaktifkan
Sistem penalti (minus poin) untuk role Mahasiswa dan Petugas sudah dinonaktifkan di kode.
✅ Isolasi Test Account
Kelompok/akun uji coba dikecualikan dari kalkulasi benchmark global kelompok.
